# AGENTS.md — GamePort

Orientation and working rules for human contributors and coding agents (Codex, etc.).

## Vision

GamePort is a native macOS app + CLI for running Windows games smoothly on Apple Silicon Macs with zero manual Wine tinkering:

1. **Isolation by default:** every game gets its own Wine prefix, Windows Steam install, and `HOME` directory. Engines are shared and read-only.
2. **Predictability:** APFS copy-on-write Steam base cloning (new profiles in seconds) plus automatic daily pre-launch snapshots and one-click rollback.
3. **Measured evidence over guesses:** a built-in Lab runs games, parses Metal HUD frame rates, detects crashes/occluded windows, and auto-selects the fastest working renderer.
4. **Future-proof graphics & engine:** open Vulkan/DirectX 12 path (KosmicKrisp + `vkd3d`) and preparation for a Rosetta-free ARM64 engine ahead of macOS 28.

## Essential Commands

```sh
# Build and run all unit tests
swift test

# After editing Data/ or Tools/kosmickrisp-shim/shim.c (embedded for installed CLI/app use):
python3 Scripts/embed-data.py

# Add missing community recipes from the pinned CC0 catalog and re-embed
python3 Scripts/import-recipes.py
python3 -m unittest discover -s Tests/ScriptTests

# Turn community reports into recipe changes (runs weekly as a pull request: .github/workflows/community-recipes.yml)
python3 Scripts/community-recipes.py

# Build release CLI
swift build -c release

# Build double-clickable build/GamePort.app (ad-hoc signed)
Scripts/make-app.sh

# Build & install patched DXVK (fixes D3D11 pipeline-statistics crash on MoltenVK)
Scripts/build-dxvk.sh

# Install KosmicKrisp + GamePort's Vulkan shim into the current engine (macOS 26+)
.build/release/gameport engine kosmickrisp <engine-id>

# Cross-build the experimental 64-bit D3D12 overlay
Scripts/build-vkd3d-proton.sh
```

Runtime data lives in `~/Library/Application Support/GamePort` (override with `GAMEPORT_HOME` for tests or isolated runs).

## Architectural Invariants & Rules

- **Shared core:** All operations live in `Sources/GamePortKit/`. Both `Sources/GamePortApp` and `Sources/gameport` call into `GamePort` rather than duplicating logic.
- **Re-embed after `Data/` edits:** `Sources/GamePortKit/Generated/BundledData.swift` is generated by `python3 Scripts/embed-data.py`. Never hand-edit it; always re-run the script when modifying `Data/`.
- **Branding in one place:** Display name, CLI name, data folder, bundle ID, and env var live in `Sources/GamePortKit/Brand.swift` (kept in sync with `Scripts/make-app.sh`).
- **Engine integrity:** Every downloaded engine component must be HTTPS and SHA-256 verified before swapping into place from staging.
- **License & clean-room rules (`CONTRIBUTING.md`):**
  - GamePort's own code is licensed under **PolyForm Noncommercial 1.0.0** (`LICENSE`), and contributions follow [CONTRIBUTING.md](CONTRIBUTING.md).
  - Do **not** copy code from Highball (GPL-3.0) or closed-source tools.
  - Wine, DXMT, and winetricks (LGPL) are downloaded and executed as separate processes, never linked.
  - Storefront/download tools (`legendary`, `gogdl`, SteamRE `DepotDownloader` (GPL-2.0), Valve `steamcmd`) are downloaded on demand (HTTPS, SHA-256 pinned where the vendor publishes a fixed build) and run only as separate child processes.
  - Never bundle, host, or mirror Apple's D3DMetal or the Windows Steam client. D3DMetal stays behind the in-app Apple license gate.
  - Never add anti-cheat workarounds or bypasses; anti-cheat data is informational only.
  - Only import CC0 recipe paths (plus the MIT anti-cheat map with notice) from `highball-db`.
- **Learning from play:** sessions go to `profiles/<id>/plays.json`; only fixes in `SelfHealing.automaticActionIDs` are applied without asking (`AutoFix`, undone if the next session fails); community results may change only the renderer and the Bridge/Windows Steam choice of unverified recipes (`CommunityAdvice`), and bundled recipes change only through a reviewed pull request.
- **Language:** English for all code, comments, UI text, recipes, and commit messages.

## Current State & Next Priorities

See [ROADMAP.md](ROADMAP.md) for the full prioritized plan across both tracks:
- **Track A (Game Compatibility & UX):** Expand and verify game recipes via the Lab, automate per-game config fixes, improve UX and onboarding, and prepare signed/notarized distribution.
- **Track B (Open DirectX 12 & Post-Rosetta ARM64):** Measure a D3D12 title (`3dmark-demo`) on Wine's `vkd3d` over MoltenVK vs. KosmicKrisp, evaluate `vkd3d-proton`, and build toward an ARM64 Wine + FEX + ARM64 DXMT engine before macOS 28 restricts Rosetta.
